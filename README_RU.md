# Music Room 1.4 — Python-сервер синхронизации

Внутри `index.html` — прежние страницы, питомцы, чат, загрузка музыки и приглашения.

`main.py` — Python FastAPI + WebSocket. **Сервер, а не устройства**, хранит последнее состояние музыки и порядковый номер команды. Гость не может отправить команду воспроизведения. Все участники получают одно состояние от сервера, а часы синхронизируются через ping/pong.

## Как опубликовать (новый адрес, НЕ прежний Netlify)

1. Создай новый репозиторий на GitHub (можно приватный). Загрузите **содержимое этой папки** в корень репозитория: `main.py`, `index.html`, `requirements.txt`, `.python-version`, `render.yaml`. Не загружайте архив как один файл.
2. Зайди на https://dashboard.render.com, выбери **New → Web Service → Build and deploy from a Git repository**, подключи репозиторий.
3. Выбери Python 3, план Free для тестов. Команда сборки: `pip install -r requirements.txt`. Команда запуска: `uvicorn main:app --host 0.0.0.0 --port $PORT --workers 1`.
4. Открой выданный Render адрес вида `https://название.onrender.com`. Дождись, пока появится Music Room 1.4. Не используй старую ссылку Netlify для новой синхронизации.
5. Ведущий должен нажать **«+ Новая комната»** на новом адресе (ключ ведущего привязан к браузеру и сайту). Нажми «Скопировать приглашение» — оно содержит правильный новый адрес. Друг открывает приглашение, отправляет запрос, ты принимаешь его.
6. Друг нажимает «🔊 Включить звук» один раз. Ведущий устанавливает MP3, запускает, ставит на паузу или перематывает.

**Supabase**: URL проекта и publishable key уже сохранены в HTML из предыдущей версии. Используются для загрузки MP3 в `room-audio`, чата и питомцев. Не вставляй service_role или другие секретные ключи в HTML.

## Проверки

- На `https://...onrender.com/health` должно быть `{"ok": true, ...}`.
- На сайте в области плеера должна появиться надпись `🐍 Подключено к Python-серверу`.
- На обоих устройствах должны быть одинаковый код комнаты и статус «Онлайн».
- Если у друга не запустился звук, нажми у него «🔊 Включить звук».

## Ограничения

- Это **тестовый прототип**, не сервис для большого количества пользователей.
- Комнаты и секреты ведущих хранятся в оперативной памяти Python-сервера. При перезапуске сервера музыка сбрасывается; ведущий может повторно открыть комнату, но состояние песни не сохраняется. Производственная версия потребует Redis/PostgreSQL и серверной проверки допуска гостей.
- Бесплатный Render может засыпать после отсутствия активности; при первом открытии тогда нужно немного времени на запуск.
- HTML5 MP3 может быть достаточно точным для совместного прослушивания, но идеальная синхронизация на уровне миллисекунд невозможна: остаются сетевые задержки, буферизация и ограничения браузеров, особенно для YouTube.
- Код комнаты — не пароль. Приглашай по кнопке, не пересылай ссылку с `#host=` или внутренние токены.
- Загрузка MP3 по-прежнему требует разрешений на распространение файлов; публичный Supabase bucket доступен любому, у кого есть прямая ссылка.

## Локально (Python 3.11+)

```sh
pip install -r requirements.txt
uvicorn main:app --host 127.0.0.1 --port 8000 --workers 1
```

Открой http://127.0.0.1:8000. Чтобы друг подключился через интернет, всё равно нужен публичный сервер (Render или другой хостинг), а не адрес localhost.
