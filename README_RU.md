# Music Room 1.5 — исправление синхронизации

Версия сохраняет разделы 1.4, чат, питомцев, загрузку MP3 через Supabase и заявки на вход. Новые функции относятся только к синхронизации музыки.

## Что исправлено

- Отдельный **индикатор Python WebSocket** в плеере. Статус `Онлайн` от Supabase сам по себе не означает, что музыка синхронизируется.
- Гость при новом подключении принимает свежий снимок Python-сервера, даже если его номер команды меньше номера до перезапуска Render.
- Поздние подтверждения старых команд больше не должны отменять новую команду ведущего.
- Гость запрашивает состояние сервера раз в 4 секунды на случай потери сообщения.
- Python добавляет номер команды к подтверждениям, проверяет роль и возвращает ошибки на неверные команды.

## Обновление GitHub и Render

1. Распакуй ZIP. В GitHub открой уже созданный репозиторий `music-room-python` → **Add file → Upload files**.
2. Загрузи **файлы из этой папки** в корень репозитория (не весь ZIP), согласись заменить старые `main.py`, `index.html` и другие файлы.
3. Нажми **Commit changes**. В Render проверь новый деплой: статус **Live**. Если автоматический деплой выключен: **Manual Deploy → Deploy latest commit**.
4. Проверь адрес `https://music-room-python.onrender.com/health`. Там должна быть запись `"version":"1.5"`. Если версия другая, Render ещё показывает старый код.
5. На компьютере и телефоне открой `https://music-room-python.onrender.com` и обнови страницу. **Создай новую комнату** на компьютере, отправь приглашение и прими запрос друга.
6. У обоих под плеером должна быть зелёная надпись `🟢 Python WebSocket подключён`. **Не проверяй синхронизацию, пока на одном из устройств надпись красная**.
7. Для проверки сначала выбери `Демо-мелодия`, затем обычную загруженную MP3. Друг нажимает `🔊 Включить звук` один раз. Ты нажимаешь `Играть`, затем `Пауза` и `+10 сек`.

## Диагностика

- `Онлайн`, но `🔴 Python WebSocket...` — Supabase работает, музыкальное соединение нет. Проверяй именно Render и /health.
- `4404` — Python-комната не существует после рестарта. На Render-сайте создай **новую** комнату.
- `4409` — уже есть другое соединение ведущего: закрой вторую вкладку на устройстве ведущего.
- MP3 играет только на ведущем, хотя WebSocket зелёный — проверь, что гость принял приглашение, нажал **Включить звук** и браузер не блокирует звук.
- MP3 не загружается на телефоне — проверь общедоступность URL в Supabase Storage и его формат.

## Ограничения

Python FastAPI работает в одном процессе (`--workers 1`). Комнаты хранятся в памяти и сбрасываются при перезапуске бесплатного Render. Полная синхронизация до миллисекунд не гарантируется: браузеры, медиа-буферизация и YouTube могут давать задержку. Авторизация гостей в Supabase пока только интерфейсная; публикация и загрузки не рассчитаны на открытый массовый сервис. Не делись токенами ведущего и не загружай файлы, на распространение которых нет прав.


## Новое в версии 1.6: Главная и поиск музыки

- Главная показывает созданного питомца с тем же именем и цветом, что во вкладке «Питомец».
- Сверху поиск: **Audius — полные треки** через публичное API, либо **Известные исполнители** — официальный каталог Apple/iTunes (ссылки на сервис).
- На Audius кнопка «Скачать» появляется **только при разрешении автора** и отсутствии download-gating. На странице Apple Music прямое скачивание не предоставляется.
- «Мои песни» на главной — локальный выбор файлов MP3/M4A/WAV/OGG для личного прослушивания и повторного сохранения. Эти файлы не отправляются друзьям и не сохраняются после перезагрузки страницы.
- Личный плеер на Главной **не синхронизируется с общей комнатой**. Синхронизация и чат остались как в 1.5, мы её не меняли.
- Для поиска нужен доступ сервера Render к внешнему музыкальному API. Если каталог недоступен или ограничивает запросы, сайт показывает ошибку.
- Новый пакет `httpx` добавлен в requirements.txt, Netlify для этой версии не нужен; обнови через GitHub и Render.


## Music Room 1.7 — известные исполнители внутри сайта

- На Главной добавлен **YouTube · известные песни**: поиск по названию или артисту, показ результатов, воспроизведение через видимый официальный YouTube IFrame Player без перехода на другую страницу. Встроенный плеер включает стандартные элементы управления, рекламу и атрибуцию YouTube. Часть видео может запрещать встраивание или иметь региональные ограничения.
- Для работы поиска требуется включить YouTube Data API v3 в Google Cloud и получить **API key**. В Render открыть **music-room-python → Environment → Add Environment Variable**: имя `YOUTUBE_API_KEY`, значение — свой ключ. **Не вставляй ключ в GitHub, HTML, скриншоты или чат.** Ключ использует только Python-сервер. После изменения Environment Render должен перезапустить сервис.
- Без API-ключа работают Audius (полные треки) и **Каталог · 30 секунд** (предпрослушивания iTunes/Apple). Для полного YouTube-поиска ключ обязателен.
- Кнопки скачивания убраны из Главной; загрузка собственных MP3 для общего прослушивания остаётся в музыкальной комнате.
- Личный YouTube-плеер на Главной не синхронизирован с гостями. Синхронизация в комнатах оставлена прежней.
- Если включена бесплатная квота Google Cloud, запросы могут быть ограничены; проверь Quotas на стороне Google Cloud.
- Обнови все файлы 1.7 в GitHub, нажми Commit changes и проверь `https://music-room-python.onrender.com/health` — там должна быть версия `1.7`.
